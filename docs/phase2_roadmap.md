## 🎯 核心演进方向深度规划

### 方向一：主从多 Agent 专业分工网络（主从解耦，终结精力分散）

#### 1. 痛点分析
当前单 Agent 模式下，同一个 LLM 既要与用户闲聊唠家常、揣摩不清晰的业务意图，又要编写严谨的 Python 代码，还要阅读自身报错自愈，容易顾此失彼；且多轮修改时容易全量重写导致已有逻辑退化。

#### 2. 落地设计
- **统筹架构师 (Planner / Orchestrator Agent)**：
  - 负责与用户进行需求对齐（例如：“主键是以订单号还是手机号为准？”、“空值是填充 0 还是直接整行剔除？”）；
  - 输出标准化的 **《工具开发规格说明书 (Task Spec)》**，并挂载对应的 Playbook。
- **代码工匠 (Coder Agent)**：
  - 接收 Task Spec，在纯净上下文中输出高质量 Python 脚本与 UI Schema。
- **调试自愈 (Fixer Agent)**：
  - 专职消费测试沙箱的失败用例和 Traceback，进行局部“增量补丁式”修复（Patching），保护已验证逻辑不受全量重写破坏。

---

### 方向二：高保真原模版「精准插槽回填」（Template Slot Injection）

#### 1. 痛点分析
政企、银行或大厂下发的预设 Excel 模版往往带有极度复杂的嵌套公式、宏代码、多层级表头和公司 VI 规范。大模型重新绘制工作簿极易损坏原有格式。

#### 2. 落地设计
- **模板与原始数据双轨输入**：
  - 用户上传【目标规范空模板】+【多份业务源表】；
- **插槽识别与只读保护**：
  - 智能识别模版的有效数据写入区域（如 `Sheet1!A5:G120`），并将所有外围公式、汇总求和列、图表引用区域完全设为保护只读；
- **In-place 无损写入**：
  - 仅替换目标单元格的值，100% 原样保留原模板的样式、字号、合并规则、透视表联动与 VBA 工程。

---

### 方向三：可视化交互决策报告（前端专家 Agent + HTML/ECharts）

#### 1. 痛点分析
高管和业务负责人不需要看几十万行的底层 Excel 原始明细，他们更需要一份**直观、开箱即用、具备交互能力的商业决策看板**。

#### 2. 落地设计
- **前端专家 Agent (Frontend Expert Agent)**：
  - 注入现代化 UI 设计规范（Tailwind CSS 精致圆角、卡片排版、深浅自适应色系）；
  - 根据聚合统计指标（`metrics.json`），自动选择最佳图表表达（趋势选面积图、占比选环状图、对比选条形图，集成 ECharts）；
  - 生成**自包含、离线可运行的单文件 `report.html`**，支持直接在前端通过 Iframe 安全沙箱（`sandbox="allow-scripts"`）预览；
  - 提供 `@media print` 样式优化，支持用户在浏览器内一键导出为像素级完美的汇报 PDF。

---

### 方向四：资产沉淀 ——「我的本地离线工具箱」（Toolbox）

#### 1. 痛点分析
当前生成的工具绑定在单个会话中，下周处理相同业务时难以复用，违背了“Agent as a Tool Maker”的长期复用价值。

#### 2. 落地设计
- **一键固化为常用工具**：
  - 经沙箱调试满意的工具，支持一键点击「📌 保存到我的工具箱」，命名为如“财务部-月末发票批量核销器”；
- **免对话独立工作台**：
  - 侧边栏常驻「工具箱」入口，普通用户无需与大模型对话，直接调出工具表单、拖入新月份的数据，0 Token 纯离线秒级执行。

---

### 方向五：底层引擎升维 —— DuckDB / Polars（百万级大表秒级处理）

#### 1. 痛点分析
遇到几百兆或数百万行的海量 CSV/Excel 时，传统 Excel 假死崩溃，Pandas 容易因全量载入内存而触发 OOM 异常。

#### 2. 落地设计
- **大数据场景智能感知**：
  - 当挂载文件 > 50MB 或行数 > 50 万时，系统动态注入 **DuckDB / Polars 专属 Playbook**；
- **本地流式 SQL 聚合**：
  - 自动生成 DuckDB 原地查询与流式管道脚本，500 万行电商流水可在 1~2 秒内原地完成分组统计；
- **拆分与下钻导出**：
  - 自动将海量聚合结果按维度（如月份、大区）分片导出为轻量级 Excel，攻克大数据“最后一公里”痛点。
