# excel-tool-harness 核心需求文档

## 📌 项目定位
一个基于 DeepSeek Harness (dsh) 的**本地化 Excel 智能处理工作站**。
核心理念是 **“Agent as a Tool Maker”**（大模型不直接处理数据，而是为你编写、组装处理数据的专用工具）。

## 🎨 界面交互 (双屏形态)
产品采用**“左侧对话开发，右侧独立运行”**的布局：

*   **左侧（对话流 / 资源管理器）：**
    *   用户与大模型对话，描述 Excel 处理需求（支持上传少量示例数据供模型参考）。
    *   每个“历史对话”在底层对应一个独立的**工具工作区（Workspace）**。
    *   用户可以通过自然语言持续修改、迭代该工具的逻辑或视图样式。
*   **右侧（工具运行沙箱）：**
    *   **独立且离线**：不依赖大模型，纯本地算力执行。
    *   **动态渲染**：根据左侧生成的配置（JSON Schema），自动生成操作界面（如：文件上传按钮、参数输入框、定制化 HTML 视图）。
    *   **确定性执行**：用户在此上传真实的、大体积的 Excel 文件，点击运行并直接下载/预览处理结果。

## ⚙️ 核心运转闭环
当用户提出需求或修改意见时，系统按以下流程运转：

1.  **理解与生成：** 大模型分析需求，强制输出两类核心资产：
    *   `Python 代码`：基于 Pandas 等库的数据处理脚本。
    *   `UI Schema`：描述右侧所需交互表单的 JSON 结构。
2.  **动态渲染：** 前端接收到 Schema，在右侧实时绘制出可视化的工具界面。
3.  **本地执行：** 用户在右侧填好参数、上传文件并点击“执行”后，Node.js 宿主服务通过子进程（`child_process`）唤起本地 Python 环境运行生成的脚本。
4.  **结果反馈：** Python 处理完毕，将结果（新 Excel 文件、报错日志或图表）回传给前端展示。

## 🛠️ MVP 阶段技术选型
*   **核心底座：** DeepSeek Harness (dsh) —— 负责 Web 宿主服务、插件生命周期调度、LLM 通信。
*   **前端渲染：** 利用 dsh 机制或轻量前端框架，实现 JSON Schema 驱动的表单渲染与 iframe 隔离沙箱。
*   **后端执行引擎：** Python (包含 Pandas, Openpyxl) —— 作为被调用的本地执行引擎，确保数据处理的专业性和准确率。
*   **架构演进路线：** MVP 阶段采用 dsh 原生模型插件；后期若面临复杂的历史上下文管理或代码 Diff 增量合并，再以插件形式无缝挂载 LangChain/LangGraph。
